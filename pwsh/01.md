# 鈴鹿黒窓小噺  
## 黒窓、思ってたのと違った？

前回は、とりあえず黒い窓を開いて、いくつか命令を打ってみました。

今回はもう少しだけ先へ進んで、

**「この黒窓で、いったい何を材料にして仕事ができるの？」**

というところを見てみましょう。

---

## 先日の小噺を少し振り返ってみよう

まずは前回と同じようにターミナルを開いてください。

そして、

**上矢印キー `↑`**

を押してみてください。

「あれ？ なんか出てきた。」

そうなんです。

前回打ち込んだコマンドたちを覚えているんです。

賢いでしょ。

何度も同じものを最初から入力する必要はありません。

出てきたコマンドを左右の矢印キーで移動して、一部分だけ書き換えることもできます。

この先、この機能にはずいぶん助けてもらいます。

---

## どんなデータを扱えるのかな？

まずは難しいことを考えず、黒窓にいろいろ入れてみましょう。

```powershell
1..10
```

これは1から10までの数字。

```powershell
1,2,5,12.55
```

整数だけでなく、小数も扱えます。

では文字は？

```powershell
"abc","xyz","漢字"
```

もちろん日本語だって大丈夫。

こんなのは？

```powershell
123,"文字",987.123
```

数字と文字を一緒に置くこともできます。

そして、

```powershell
date
```

現在の日付と時刻が出てきます。

---

## とりあえず `| ogv` してみよう

前回登場した `ogv` を、今のデータの後ろにつけてみましょう。

たとえば、

```powershell
1..10 | ogv
```

あるいは、

```powershell
"abc","xyz","漢字" | ogv
```

さっき黒窓に表示されていたものが、別の窓で見えるようになりました。  
なにやら上の項目名を見ると現在表示しているデータのExcelとかでおなじみの型のようなものが見えますね、。  
もう一度、先ほどのdateの内容に|ogvを付けてみてみましょう。  

![date-ogv(.png)](/images/date-ogv.png){: width="800px" }

先ほどまでと違ってずらずらと複数の項目が表示されています。  
dateコマンドレットは単に文字情報で日付を返すだけでなくていろいろなところで使えるオブジェクトと言う形のデータを返すからなんです。詳しくは近々。

このように、この連載では、しばらく

**「何か出てきたら、とりあえず `| ogv` して眺めてみる」**

くらいの使い方をしていきます。

件数が増えて黒窓では見づらくなったときにも便利です。

---

## `date` と `"date"` は同じ？

ここで、ちょっとだけ大事な話。

次の2つを試してみてください。

```powershell
date
```

```powershell
"date"
```

見た目は似ていますが、やっていることは違います。

`date` はPowerShellに対する命令として働きます。

でも、

```powershell
"date"
```

と `" "` で囲むと、これはただの**文字データ**です。

同じように、

```powershell
Get-Process
```

と、

```powershell
"Get-Process"
```

も違います。

前者はコマンドとして働き、後者はただの文字です。

PowerShellが扱っているデータには、実は「これは数字」「これは文字」「これは日付」といった**型**があります。

今は型について詳しく覚えなくても大丈夫。

とりあえず、

**黒窓の中では、命令とデータはちゃんと区別されている。**

くらいに思っておいてください。

## ただ数字が並んでも面白くない？

ここまで、

```powershell
1..10
```

のようなものを試してきました。

でも、

**「数字が並んだだけで、これの何が役に立つの？」**

と思いますよね。

まあ、そう言わずにもう少しだけ見てください。

今度は少し数を増やして、

```powershell
1..40
```

としてみます。

1から40まで並びました。

では、この数字をパイプ `|` で次の処理へ渡してみましょう。

```powershell
1..40 | % { $_ * 3 }
```

今度は、

```text
3
6
9
12
15
...
```

と出てきました。

1から40までの数字を、ひとつずつ3倍した結果です。

ここで出てきた `%` は、左から流れてきたものを**ひとつずつ処理する**ための短い書き方です。

そして `$_` は、

**「今、パイプを流れてきたもの」**

くらいに思ってください。

つまり、

```powershell
$_ * 3
```

は、

**「今来た数字を3倍してね」**

という感じです。

今は `%` や `$_` を覚えなくても大丈夫。

それよりも、

**同じ `1..40` でも、後ろの処理を変えると結果が変わる**

ところを見てください。

---

## 今度は3の倍数を探してみよう

では、こんなのはどうでしょう。

```powershell
1..40 | % { $_ % 3 -eq 0 }
```

おや？

```text
False
False
True
False
False
True
...
```

数字ではなく、`True` と `False` が並びました。

これは、

**「その数字を3で割った余りが0ですか？」**

と、ひとつずつ調べた結果です。

`True` なら「はい」。

`False` なら「いいえ」。

では、`True` のものだけ残すことはできないでしょうか。

できます。

```powershell
1..40 | ? { $_ % 3 -eq 0 }
```

今度は、

```text
3
6
9
12
15
...
```

となりました。

3の倍数だけが残りましたね。

`?` は、条件に合うものだけを残すための短い書き方です。

---

## 同じ材料でも、遊び方はいろいろ

もう少し遊んでみましょう。

たとえば、3の倍数だけ文字を変えてみます。

```powershell
1..40 | % { if ($_ % 3 -eq 0) { "Fizz" } else { $_ } }
```

3の倍数だけ `Fizz` になりました。

では、3の倍数なら `Fizz`、5の倍数なら `Buzz`。

両方なら……

そう、よくプログラミングの練習で登場する **FizzBuzz** です。

```powershell
1..40 | % {
    if ($_ % 15 -eq 0) { "FizzBuzz" }
    elseif ($_ % 3 -eq 0) { "Fizz" }
    elseif ($_ % 5 -eq 0) { "Buzz" }
    else { $_ }
}
```

同じ `1..40` なのに、ずいぶん違うものが出てきました。

さらに、こんな遊びもできます。

3の倍数のときだけ、ちょっとアホになってもらいましょう。

```powershell
1..40 | % {
    if ($_ % 3 -eq 0) { "$_ アホ！" }
    else { $_ }
}
```

世界のナベアツ風ですね。

---

## 材料は同じ。後ろを変えただけ

ここで見てほしかったのは、FizzBuzzの書き方ではありません。

最初の材料は、ずっとこれです。

```powershell
1..40
```

その後ろにつなぐ処理を変えただけで、

* 3倍する
* 条件を調べる
* 3の倍数だけ取り出す
* FizzBuzzにする
* ちょっとアホになってもらう

と、いろいろな結果を作れました。

**材料を用意して、パイプで次の処理へ渡す。**

そして、

**後ろにつなぐ処理を変えれば、同じ材料から違う結果を作れる。**

これが黒窓で仕事をするときにも、かなり大事な感覚になります。

とはいえ、

**「数字で遊べるのは分かったけど、仕事では1から40なんて使わないよ」**

ですよね。

では今度は、もっと仕事で見かけそうなデータを材料にしてみましょう。

次はCSVです。

## 初めての「変数」

せっかく読み込んだデータです。

この後も何度も使いたい。

そこで登場するのが**変数**です。

難しそうな名前ですが、今は

**「一時的にデータを覚えておく入れ物」**

くらいに考えてください。

上矢印キー `↑` で、さっきの `Import-Csv` を呼び出します。

そして行の先頭へ移動して、

```powershell

```

を追加します。

つまり、

```powershell
$csv = Import-Csv ＜CSVファイルのパス＞
```

という形です。

これで、読み込んだCSVのデータを `$csv` という名前の入れ物に置いておけます。

本当に入っているでしょうか？

```powershell
$csv
```

Enter。

```powershell
$csv | ogv
```

## 同じ材料を、いろいろな道具に通してみる

ここからは `$csv` を材料にして、後ろにつなぐものを変えて遊んでみます。

まずは、

```powershell
$csv | Select-Object
```

次は、

```powershell
$csv | Sort-Object
```

そして、

```powershell
$csv | Measure-Object
```

さらに、

```powershell
$csv | Where-Object
```

「あれ？ 何も変わらない」

「これは何を指定すればいいの？」

そんなものもあります。

それでOKです。

これらは後の回で少しずつ使い方を覚えていきます。

今日は、

**同じ `$csv` という材料でも、パイプ `|` の後ろにつなぐ道具を変えられる**

ということだけ見ておきましょう。

そして結果が長くて見づらければ、

```powershell
| ogv
```

を最後につけて眺めてみてください。

## 必要なデータだけ別の箱へ

では、少しだけ加工らしいことをしてみます。

たとえば、このCSVから18歳～40歳の人だけを取り出してみましょう。

```powershell
$justzone = $csv | Where-Object { $_.年齢 -ge 18 -and $_.年齢 -le 40 }
```

※ `年齢` の部分は、配布するCSVの実際の項目名に合わせてください。

ちょっと急に暗号っぽくなりましたね。

今は全部理解しなくて大丈夫です。

やっていることは、

**「`$csv` から18歳～40歳だけを選んで、`$justzone` という別の入れ物に入れた」**

だけです。

確認してみます。

```powershell
$justzone | ogv
```

人数も見てみましょう。

```powershell
$justzone | Measure-Object
```

**材料も道具も差し替えられる**

ということ。

黒窓が少し「仕事をする場所」に見えてきたでしょうか。

## 本日の用語集

### `Import-Csv`

CSVファイルをPowerShellに読み込むコマンドレット。

### 変数

データを一時的に覚えておく入れ物。

PowerShellでは `$csv` のように、名前の先頭に `$` をつけます。

### パイプ `|`

左側の結果を右側へ渡すもの。

この先、何度も登場します。

### `Out-GridView` / `ogv`

データを別のウィンドウで表のように眺めるためのコマンドレット。

`ogv` は `Out-GridView` の短い呼び方です。

### `Select-Object`

データから必要な項目などを選ぶためのコマンドレット。

### `Sort-Object`

データを並べ替えるためのコマンドレット。

### `Measure-Object`

件数や合計、平均などを調べるためのコマンドレット。

### `Where-Object`

条件に合うデータだけを選び出すためのコマンドレット。
